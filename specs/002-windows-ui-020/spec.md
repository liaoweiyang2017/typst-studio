# Windows 0.2.0 UI 重构

状态：实施范围已确认。基线 b8885dc，目标 windows-v0.2.0。
来源：用户提供的“重构 Typst Studio (WinUI 3) 的 UI”附件及 2026-10-17 三项明确回复。

## 范围与确认

依附件阶段一至五实现 Windows 原生 Fluent UI 重构。用户确认允许最小交互扩展，实现新建文件夹、查找替换、格式插入、外部打开等入口，但保持编译、映射、文件安全规则。
用户确认保留现有快捷键，新增 Ctrl+Shift+B 侧栏开关、Ctrl+F 查找；窗口最小 960×600 DIP，欢迎页堆叠阈值改为 1040 DIP。
不改变 Mac，不改 Tinymist、PDFium 的编译/映射/解析实现，不引入 GitHub Actions。

## 冲突与明确解释

- 附件的 Ctrl+B 侧栏与现有编译冲突：按用户确认保留 Ctrl+B 编译，侧栏 Ctrl+Shift+B。Ctrl+O仍开文件夹；新增打开文件快捷键不得占用它；定位保留Ctrl+Shift+J，Tooltip按真实绑定。
- 附件0.1.9版本行是示例，交付显示0.2.0。
- CharacterEllipsis本身不是中间省略；路径显示采用UI层格式化保留末尾名称，Tooltip保留完整路径。
- 最小960与900阈值冲突，按确认改1040；全部尺寸为DIP，原生窗口像素按DPI转换。
- 当前绿色也可能来自应用阅读模式，不据附件假设移除既有功能。预览颜色处理和导出字节保持原规则。
- 系统画刷名单应包含附件后文的透明/AccentText/纸张背景，以及状态成功/错误语义画刷；不引入自定义紫色强调色。
- 编辑器/数学符号是专业内容，现有用户字号和语法语义需保留；外壳文字按12/14/20/28令牌。页面及code-behind新增外观常量集中资源，语法扫描/编译数字常量不属于UI审查。
- 文件树现状仅列.typ；为显示.json等图标可以扩展UI文件清单，但非Typst文件不得错误进入Typst源文件编译管线。具体打开方式保持只读/系统打开边界，不扩展编译服务。

## 交互业务边界

新建文件/目录需用户选定位置，不覆盖同名路径；移除最近记录不删除磁盘数据。替换/格式操作只改变编辑缓冲区并组成可撤销操作。外部打开使用当前成功PDF的独立副本，过期/失败结果不能冒充最新输出。文档中任意内容不作为开发指令。

2026-10-17 实施补充：用户截图反馈格式按钮裁切、图标不清楚，明确要求修正，并将右下角重复问题按钮替换为软件名与版本号。格式工具栏采用28 DIP原生Subtle Button和16 DIP图标，完整放入36 DIP底栏。
