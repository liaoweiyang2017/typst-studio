## 目标与范围

为当前桌面 Typst 编辑器建立可追踪基线，再由用户指定下一轮改动。
本轮只建立开发流程和规范草案，不预设新版本、不改产品功能、不迁移技术栈、不触发打包发布。

## 业务规则与当前边界

- 文件编辑只在用户授权的工程范围内进行；保存遇到外部变更应报告冲突，不能静默覆盖。
- 当前工程搜索限 Typst 源码；包含内存中未保存的缓冲区，最多 200 个命中行，跳过大于 1 MB 的磁盘文件，排除生成快照。
- 大纲优先使用主 PDF 的书签和层级；没有 PDF 时回退到当前源码标题。旧 PDF 的大纲应明确其状态。
- 符号插入应考虑数学环境中的转义、注释和原始文本，插入应可撤销。
- 后台结果必须与当前工程、文档版本和查询一致；取消、切换工程或关闭窗口后，不得覆盖新状态。
- 初次启动无需下载编译器；首次使用未缓存的第三方 Typst 包可能联网。
- Windows ARM64 与 x64 分别构建；既有 x64 测试基于 Windows ARM 模拟，不视为实体 x64 验证。

## 待澄清与潜在冲突

1. 下一轮目标、平台、优先级和版本号尚未指定，不能据此生成具体功能编码任务。
2. “与 Mac 一致”是否包括 md/json/bib 等非 Typst 文件搜索？Windows 现状仅搜索 .typ。可选择维持并明确范围，或另立扩展需求；不自动扩大。
3. “离线可用”是否包括未缓存第三方包？现状仅保证内置编译器。完整离线需要另行定义包分发、更新和许可策略。
4. “快”和“精确”需要测量口径。待确定代表性工程、硬件、冷/热启动、响应分位数，以及定位允许的偏差；不虚构数值承诺。
