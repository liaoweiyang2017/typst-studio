# Typst Studio 0.2.1：显式编译与稳定预览入口

状态：已确认。用户明确选择“按钮编译当前文件，保留编辑后自动更新”。Windows/macOS同时发布0.2.1。

## 用户问题与目标

切换编辑文件的行为在两端不同，用户需要明显的编译按钮；PDF反向定位进入子文件后，不应生成子文件的独立PDF、替换原预览。保持原生UI、Tinymist缓存、公式及跨文件映射、文件安全和响应速度。

## 已确认业务规则

1. 区分正在编辑的文件与编译入口。打开工程时识别入口并首编译；打开独立文件/新建文档时以该文档为初始入口。
2. 同工程文件树、搜索、错误列表、PDF反向定位切换编辑文件时，不切换编译入口，不触发额外编译，不重置PDF阅读位置。
3. 保留编辑后的自动编译：修改入口或其包含的文件时，更新同一个入口的完整文档；Windows尊重已有自动编译开关。单纯切换文件不算编辑。
4. 工具栏显式“编译”按钮编译当前正在编辑的文件，并将它设为新的预览入口。Windows Ctrl+B、Mac Cmd+B、菜单与按钮行为一致。
5. 不增加入口选择下拉菜单。入口变更由显式编译当前文件完成；提示显示当前编辑文件和预览入口的区别。入口在当前会话有效，不新增工程配置格式。
6. 编译中有原生进度反馈；重复请求合并/取消旧结果，旧任务不得覆盖新入口结果，编辑与滚动继续可用。
7. 失败保留上次成功PDF并明确标为旧预览；失败/过期映射不得误跳。未保存编辑不静默落盘，不改变既有外部修改冲突保护。
8. 新按钮中英文；Mac使用Swift/AppKit原生工具栏与SF Symbols；Windows使用现有WinUI/Fluent紧凑按钮和MenuFlyout。布局不遮挡原有定位、文件名与系统窗口按钮。

## 验收标准

- CT01 两端打开main.typ工程完成首编译；普通切换子文件后入口、PDF内容和阅读位置保持，且无额外编译请求。
- CT02 在PDF中文/公式处反向定位到跨文件源码，编译入口/PDF不变；连续定位仍可用。
- CT03 编辑包含文件后，完整main PDF更新，源码磁盘保持原样；自动编译关闭时等待显式编译。
- CT04 显式按钮/既有快捷键编译当前编辑文件；点击可单独编译子文件，再切回main并点击恢复主入口；界面标识目标。
- CT05 快速切换/重复编译/编译中逆向定位不会产生入口混淆、旧结果覆盖、无响应；无效定位明确提示。
- CT06 独立子文件编译失败保留旧PDF、标为过期，不套用新入口映射；修复后恢复。
- CT07 中英文、亮暗色和各端原生工具栏完整显示；已有编辑、撤销、保存冲突、PDF阅读模式和导出回归通过。
- CT08 本地生成Windows ARM64/x64与macOS ARM64安装包，版本0.2.1；源代码私人仓库、二进制公开Release、校验和一致，不运行GitHub Actions；保留两端独立更新源。

## 边界

不升级Tinymist/PDFium，不迁移UI框架，不重写源码映射，不添加入口推断框架。未渲染内容/外部包位置仍遵循既有规则。
